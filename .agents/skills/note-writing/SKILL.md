# note 執筆

人間の意図と文体を保ったまま、note 向け Markdown を作り、同じ note-md rules で機械検査する。自動投稿は行わない。

## ワークフロー

1. 読者、記事の目的、伝えたい一次情報、希望する文体を既存の依頼・資料から特定する。結果を大きく変える情報だけが欠けている場合は確認する。
2. リポジトリ内では `docs/format-reference.md` と `docs/validator.md` を読む。note の仕様を断定するときは、必要に応じて note 公式ヘルプで現行情報を確認する。
3. 一つの H1 をタイトルにし、H2/H3 で読みやすく構成する。人間の経験・判断・根拠を中心にし、未確認の事実や出典を作らない。
4. 画像には内容を伝える代替テキストを付ける。純粋な装飾画像だけは直前に `<!-- note-ignore-next-line -->` を置き、意図的な空 ALT だと明示する。
5. 保存後、次のいずれかで検査する。

   ```sh
   note-md check --strict path/to/article.md
   # リポジトリ内で CLI が未導入の場合
   node dist/cli.js check --strict path/to/article.md
   ```

6. error と warning がなくなるまで本文を修正する。ルールを無効化する場合は、理由を利用者へ伝え、最小の rule ID だけを `--disable` へ渡す。
7. VS Code では「note プレビューを開く」で最終表示を確認する。公開用の本文はプレビューの「本文コピー」を使い、タイトルは「タイトル」を使う。

## 安全境界

- note への投稿、ブラウザ操作、公開ボタンの操作を自動化しない。
- ローカル画像の外部アップロードは、利用者が明示的に求め、表示された同意内容を承認した場合だけ行う。
- token、cookie、upload credential、生成した一時 URL をファイルやログへ保存しない。
- validator の無効化や HTML による回避より、Markdown source を修正する。

## 完了条件

- 記事が依頼の読者・目的・文体に合っている。
- `note-md check --strict` が終了コード 0 になる。
- 画像、リンク、引用、出典が確認済みである。
- プレビューでタイトル、本文、見出し、数式・ルビなどの使用機能を確認したか、未確認であることを明示する。
- 人間が最終確認し、note にコピー＆ペーストして公開できる形で渡す。
